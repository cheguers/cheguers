# Pre-registration: does a hybrid graph-vector store help an AI agent answer retrieval questions?

Status: draft v1, written before any agent trial is run. Changes after data collection must be listed as deviations.

## Question

CheguersDB claims that vector search, bounded graph expansion and a fixed weighted rerank give useful,
deterministic context for retrieval-augmented generation. The software paper
(`docs/paper/cheguersdb-softwarex.tex`) reports latency only and states that it has no retrieval-quality
evaluation. This study tests whether an agent that uses CheguersDB answers relational retrieval questions
more accurately than agents that do not.

## Arms

| arm | tools available to the agent | purpose |
|---|---|---|
| files | files, grep, python | no-database baseline |
| sqlite3 | sqlite3 CLI over the same data (vectors as BLOB, cosine computed by the agent) | structured-store control |
| cheguers-full | `cheguers` CLI, `hybrid` with graph expansion, mandatory use | treatment |
| cheguers-vector | `cheguers` CLI, `vec-search` and `hybrid --expand-depth 0`, mandatory use | ablation of graph expansion (RQ2) |

Calibration only: `closed-book` (no corpus; floor) and `gold-context` (supporting facts supplied; ceiling).

All arms share the model (claude-haiku-5-5 through the Claude subscription), the corpus, the embedding
function, the time budget, and the answer format.

## Data

Generated by `bench/agent-eval/gen/generate.mjs <outDir> <seed> <perStratum>`.

- Corpus: 1,400 papers, 700 authors, 80 organizations, 40 venues (2,220 records, 8,469 edges).
- Relations: PRESENTED_AT, AUTHORED_BY, AFFILIATED_WITH, CITES.
- Decoys: about a quarter of papers share topic and setting with another paper, so they differ only by
  modifier. About a third of organizations and a fifth of authors have near-identical names.
- Strata: `hop0` (text lookup), `hop1` (paper to venue), `hop2` (paper to author to organization),
  `hop3` (paper to cited paper to author to organization), `filter` (venue and organization name filters
  with a 2-hop traversal).
- Gold answers are computed from the graph and checked by a second computation. They are stored in
  `gold.jsonl`, which the agent never sees. The manifest records SHA-256 hashes of corpus, edges and gold.
- Scenario = one seed and `perStratum` questions of one stratum. Primary analysis: seeds 1 to 6.

## Metrics

- Primary: per-question set F1 between the agent's answer ids and the gold ids. Empty gold is not used.
- Secondary: exact match, tool calls, CLI call count, wrong-id rate (returned ids not in gold), and
  failure type (build/install, timeout, unparsable answer). Failures are reported separately and excluded
  from accuracy, with counts shown for each arm.
- Retrieval-only (no LLM, RQ5): recall@k, MRR and multi-hop completeness for `hybrid`, `vec-search`, BM25
  and brute-force cosine on the same questions.

## Hypotheses

- H1: `cheguers-full` has higher mean F1 than `files` on hop2, hop3 and filter strata.
- H2: `cheguers-full` has higher mean F1 than `cheguers-vector` on hop2 and hop3, and no difference on hop0 and hop1.
- H3: `cheguers-full` is no lower than `files` on hop0 (mandatory use adds no accuracy cost on lookups).

These are one-sided tests at alpha 0.05, with Holm correction across the three comparisons.

## Analysis

- Paired by scenario across arms. Within a scenario, repeats are averaged.
- Bootstrap 95% CI on mean F1 per arm and stratum, with 10,000 resamples over scenarios.
- Paired permutation test on the per-scenario difference.
- Effect size reported with CI. Per-stratum tables are the main result; the pooled mean is secondary.
- Failures reported per arm. A large failure gap between arms is a result in itself and is not hidden.

## Fixed settings

- Hybrid defaults as in the paper: seeds 10, expansion depth 1 for `cheguers-full`, expansion depth 0 for
  `cheguers-vector`, direction `both` (the CLI uses `both` regardless of `--direction outgoing`, so it is
  not varied), weights (0.6, 0.3, 0.1).
- Embedding function identical in all arms, decided before the pilot and recorded in the manifest.
- Corpus size is 2,220 records. The size is set so that the question and the answer fit in the agent's working
  environment; it is not a memory limit of the store. Latency at larger sizes is reported separately in the paper.

## Threats to validity

- Synthetic corpus: the answers are designed around graph structure. Phase 2 (not in this preregistration)
  may repeat the study on a public multi-hop QA dataset.
- Single model, single corpus generator, rate limits on the subscription, and one embedding model.
- The cheguers CLI silently ignores `--direction outgoing`. This is documented, not fixed.
- Unindexed property filters and an exact vector scan limit scalability; the study does not measure scale.

## Deviations (recorded after data collection)

Every departure from the draft above, in the order it arose. The paper's "Threats to validity and
deviations" section repeats this list.

1. **Embedder.** The draft did not fix an embedder. A lexical 256-dimension hash embedder was used in the first
   pilot; all arms were at ceiling, so the embedder was replaced by all-MiniLM-L6-v2 (384-d, `fastembed` 0.9.0)
   before the reported runs. Every arm in the reported runs uses this embedder.
2. **Bulk loading.** The `cheguers` CLI has no bulk relationship command, so the loader uses the library bulk API
   (`tasks/assets/load_cheguers.ts`). It is not the CLI.
3. **Invalid first attempt (database-arm corpus leak).** The first full run placed the full corpus file, whose text
   states every relation, inside the database-arm images. The database arms could therefore read the graph as text.
   Those runs are archived and excluded from every reported number. The reported runs keep the corpus only in the
   store directory, which the install step deletes, and give the files arm the corpus as its only data file.
4. **Edge and corpus store.** The store directory (edges, vectors, corpus and loader scripts) is deleted in the
   container after loading, so database arms cannot read edges or records as files.
5. **Files arm.** The files arm uses a task variant that holds the corpus and the question file only. The loader
   scripts are not in its image.
6. **Turn budget.** A 12-turn budget (`ARM_MAX_TURNS`, enforced with `claude --max-turns`) was added before the
   reported runs. It is not in the draft. Trials that exhaust it still write partial answers; unanswered questions
   score zero. Budget exhaustion is reported as a separate count.
7. **Repeats.** Three repeats of the four main arms, averaged within scenario before testing, as the draft requires.
8. **Calibration arms.** Closed-book (no data) and gold-context (only the supporting records for each question) were
   specified in the draft but not built at the time of the draft. They are built and reported, one repeat each.
9. **Multiple comparisons.** Holm correction is applied across all six pre-registered tests, which is stricter than
   the draft's scheme of Holm across the three hypotheses.
10. **Retrieval gate.** The gate criterion (hybrid beats vector-only on multi-hop completeness at top 20) was not
    met: hybrid equals vector in every stratum. `retrieval-eval/gate.mjs` is an independent proxy for the paper's
    Algorithm 1: it uses raw cosine seeds, omits the edge-weight factor and the state cap, and seeds from the top
    20 vector hits only. The study continued because the gate does not model repeated agent searches.
11. **Retrieval-only comparisons not implemented.** The draft's RQ5 comparisons (BM25, MRR, brute-force cosine) were
    not implemented. The retrieval-only evidence is the top-20 recall proxy in item 10 only.
12. **SQLite interface.** The draft says "sqlite3 CLI". The sqlite3 arm instructs the agent to use the Python
    `sqlite3` module (`agents/arms_agent.py`), which gives the agent the same SQL access.
13. **Scorer.** The first scorer did not report budget-exhausted trials and reported two-sided p-values. The reported
    scorer is one-sided, as the draft requires, and reports budget exhaustion and no-score failures in separate
    columns (`analysis/score.py`).
14. **Test answer guard.** The answer scorer now scores a non-object answer as zero. The earlier scorer raised an
    error for such answers, which was counted as a missing score.
15. **CLI direction.** `cheguers hybrid --direction outgoing` is ignored; the CLI always uses both directions.
    Documented, not fixed.
